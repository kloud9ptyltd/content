02

Setup — 5 minutes.

Everything below runs locally. No TradingView API, no credentials, no data sent anywhere.

1

Get the two apps

You need TradingView Desktop (the app, not the website) and Claude Code (free with any Claude plan). Node.js 18+ if you don't have it.

→ tradingview.com/desktop · claude.com/code · nodejs.org
2

Install the bridge

Clone the open-source MCP server and install its dependencies.

Clone & install
git clone https://github.com/tradesdontlie/tradingview-mcp.git ~/tradingview-mcp
cd ~/tradingview-mcp && npm install
3

Launch TradingView in debug mode

The bridge talks to the app through Chrome DevTools Protocol, so TradingView must start with a debug flag. Quit TradingView first, then run:

Launch with the debug flag
open -a TradingView --args --remote-debugging-port=9222
Windows: run scripts\launch_tv_debug.bat from the repo instead. Every restart of TradingView needs this flag — if you open it normally later, the connection drops until you relaunch this way.
Verify the debug port
curl http://127.0.0.1:9222/json/version
That should print JSON. Use 127.0.0.1, not localhost — localhost can resolve to IPv6 and fail.
4

Connect it to Claude Code

Register the MCP server
claude mcp add --scope user tradingview -- node ~/tradingview-mcp/src/server.js
User scope = available in every project. Verify with claude mcp list — you want tradingview ✔ Connected.
5

Test it

Open a new Claude Code session and ask:

Health check
Use tv_health_check to verify TradingView is connected.
03

What it can actually do.

Five real prompts, five real outcomes on the live chart.

"Go through my watchlist and give me the best chart to trade"

Claude flipped the chart through every watchlist symbol, pulled 150 daily candles each, computed trend/momentum/volatility for all of them — and picked the strongest setup, with reasoning.

Watchlist scan
Go through my watchlist and give me the best chart to trade right now.
The scan's pick, opened automatically on the chart — indicators and news panel included.

"Draw my trade plan with Pine Script"

Claude wrote a Pine v6 indicator — entry, stop, take-profit with risk/reward shading, supply zone, moving averages, alert conditions — compiled it in the Pine editor and applied it to the chart. Every level is an editable input.

Draw the trade plan
Draw the TSLA chart with entry, stop loss, take profit and any needed indicators using Pine Script.
TSLA daily — blue entry, red stop, green target, supply zone box: all drawn by one prompt.

"Give me a Bitcoin trade setup, update the chart"

Same flow on crypto: Claude read the structure (a liquidity sweep off the lows), built the setup with confirmation trigger and invalidation, and put it on the chart — including three ready-to-enable alert conditions.

BTCUSD daily — entry, stop under the sweep low, target in front of supply, breakout trigger line.

"Turn it into a strategy and backtest it"

An indicator draws levels; a strategy can be tested. Ask Claude to convert the plan into a Pine strategy() — entries, exits, stop and target as real orders — then open the Strategy Tester. It reads the results back: net profit, win rate, profit factor, max drawdown and the trade list.

Convert & backtest
Convert this trade plan into a Pine v6 strategy with entry, stop and target orders. Compile it, open the Strategy Tester, and tell me the net profit, win rate, profit factor, max drawdown and number of trades.
Why it matters: most AI chart posts stop at a pretty picture. A backtest is the difference between a setup that looks good and one that survived history. Fewer than ~30 trades or a suspiciously perfect equity curve is a red flag, not a green light.

"Audit the strategy — is it real or overfit?"

Now make Claude interrogate its own work. It reviews the strategy code and the backtest stats for the ways strategies lie: curve-fit parameters, too few trades, look-ahead bias, no out-of-sample check, and rules that only worked in one regime.

Audit for overfitting
Audit this strategy for overfitting and bias. Check: how many inputs were tuned, whether any rule uses future data, trade count and sample size, performance in different market conditions, and what would break it. Be skeptical — argue the bear case against your own strategy.
This is the whole edge. An AI that only ever agrees with itself is dangerous. Forcing it to attack its own idea is how you avoid trading a hope with extra math. The final call — and every real order — stays with you.
04

Test Fable 5.1 vs GPT-6 Astra yourself.

Two experiments we ran on camera with the same input to both models, so anyone can repeat them in TradingView and judge for themselves.

Test 1: the hidden-future call (4H chart)

A single prediction on a real chart, future hidden, one shot each.

  1. Chart. BTCUSDT on one venue (e.g. BINANCE:BTCUSDT), 4-hour candles, clean chart: candles + volume only, price scale on.
  2. Hide the future. Open Bar Replay and pause it at 21 days ago, 00:00 UTC (e.g. 2026-08-23 00:00 UTC on 13 Sept 2026) — say the rule out loud, never pick the bar by eye.
  3. Frame it. Show ~250 candles (~6 weeks). Hide the time scale so dates don't leak (chart settings → scales).
  4. Export. Camera icon → "Save image"; optionally also a 3-month daily chart for context.
  5. Ask both models. Fresh chat in each, memory and custom instructions off, no web or tools, strongest reasoning tier on both, one shot, no regenerate. Send the identical image + prompt.
  6. Mark the calls. Draw each model's call with the Long/Short Position tool (entry, stop, target), colour one gold and one green, label them.
  7. Resolve. Press play on replay and watch both resolve. If a script didn't compile, paste back exactly once: "It didn't compile. Error: [paste]. Fix it." and count it.
Test 1 prompt
Paste verbatim, image attached, into a fresh chat with each model.
You are being tested against another AI on the same chart. One shot, no retries.

Attached is a TradingView chart of BTCUSD, 4-hour candles. The future is hidden:
bar replay is paused at the last visible candle. You know nothing after that
candle. Do not ask for more data. Do not use web search or tools.

TASK 1 — THE CALL (max 60 words, this goes on screen):
Direction (LONG / SHORT / NO TRADE), entry price, stop price, target price, and
the one reason in plain English. The stop must be a real level visible on the
chart. The target must be at least 2x the stop distance. Give a confidence
from 0-100%.

TASK 2 — THE RULES (Pine Script v6):
Write a strategy() script that encodes the SAME logic as your call so it can be
backtested on this chart: entry condition, stop, target, one position at a time,
100% of equity, no pyramiding, commission 0.05%. Use strategy.exit with stop and
limit. It must compile first try in TradingView with no warnings. No repainting
(no request.security with lookahead, no realtime-bar tricks). Under 60 lines.

OUTPUT FORMAT, EXACTLY:
CALL: <LONG/SHORT/NO TRADE> | ENTRY <price> | STOP <price> | TARGET <price> | CONF <n>%
WHY: <one sentence>
PINE:
```pine
...
```
What we saw: across three rounds on 4H and daily both models picked the same direction and the trade either never filled or hit its stop — a single call is a coin flip, which is why Test 2 exists.
Daily chart variant: pause at the later of the two models' training cutoffs (we used 2026-07-01 00:00 UTC) so neither can remember the answer; ask each model its cutoff in a separate chat first.
Test 2: write a strategy, we backtest it

No image this time — both models design a Pine strategy, the numbers decide.

  1. Same prompt to both, no image.
  2. Save separately. Pine editor → paste → "Save as" with different names (Fable_R2, Astra_R2) so they don't overwrite each other → Add to chart.
  3. Set the date range. Strategy Tester → Properties → set the backtest date range identically for both: in-sample 2024-01-01 → 2025-12-31, then out-of-sample 2026-01-01 → today (the one that counts, neither model has seen 2026).
  4. Screenshot. Overview tab for each window: net profit, max drawdown, profit factor, total trades, percent profitable, and the buy-and-hold line.
  5. Score it. Winner = higher out-of-sample net profit; disqualified if fewer than 30 trades or max drawdown above 30%; always show buy-and-hold beside both.
Test 2 prompt
Paste verbatim, no image, into a fresh chat with each model.
You are competing against another AI. One shot, no retries, no questions back.

Design a complete trend-following or mean-reversion strategy for BTCUSDT on the
4-hour chart and write it as a Pine Script v6 strategy() that I will backtest
in TradingView exactly as you deliver it.

Constraints:
- Fixed parameters. No optimisation, no "tune this". Choose the values yourself.
- Long and short allowed, one position at a time, no pyramiding.
- Every trade has a stop and a target or trailing exit via strategy.exit.
- initial_capital=10000, default_qty_type=strategy.percent_of_equity,
  default_qty_value=100, commission_type=strategy.commission.percent,
  commission_value=0.05, slippage=2.
- Must take at least 30 trades in a typical 2-year window (a strategy that
  rarely trades is disqualified).
- No repainting, no lookahead, no request.security with lookahead_on,
  no realtime-bar tricks.
- Under 80 lines. Compiles first try with no warnings.

Output format, exactly:
NAME: <strategy name>
LOGIC: <3 sentences: entry, exit, why it should have edge on BTC 4H>
EXPECTED: <one line: what you expect it to do in trend vs chop>
PINE:
```pine
...
```
  • Layout gotcha: in a multi-chart layout, "Add to chart" applies the script open in the editor to the chart you last clicked, and editing a script updates every chart using it — save two separately named scripts.
  • Replay gotcha: bar replay does not reliably drive both charts of a layout, so run the visual on ONE chart with two coloured position tools, and use the two scripts one at a time for the tester numbers.

Max reasoning makes the shown reasoning more thorough, not the price call more skilful; the scoreboard over many rounds is what carries meaning.

05

Good to know.

  • It's your account, your limits. On the free/Basic plan TradingView allows 2 indicators per chart — Claude works within that (it swaps indicators in and out). Paid plans remove the friction.
  • All local. The bridge connects to the app on your machine only — no TradingView API, no credentials, no data sent anywhere.
  • AI can be wrong. Treat every setup as a starting point, not a signal. Size your own risk.
